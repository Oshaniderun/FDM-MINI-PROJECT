## Decision Matrix

| Issue / Challenge | Empirical Evidence from Data | Decision Made | Rationale & Justification | Alternatives Considered & Rejected |
| :--- | :--- | :--- | :--- | :--- |
| **1. Identifiers (`UDI`, `Product ID`)** | `UDI` is a unique index ($1 \dots 10000$). `Product ID` has 10,000 unique values whose 1st letter exactly duplicates `Type` ($100\%$ match). | **Drop both `UDI` and `Product ID`** completely. | Preserving unique serial strings causes decision trees/neural networks to memorize noise and overfit arbitrarily, causing fatal data leakage. | *Target encoding or hash encoding:* Rejected because serial identifiers contain zero physical signal and cannot generalize to new unseen machines. |
| **2. Time & Ordering (`Date`)** | `UDI` order does not match `Date` order. Telemetry spans 9.3 years (2014–2023) across 120 machines with irregular multi-week sampling gaps. Failure physics remain stationary over time. | **Drop `Date` from feature vector**; use **Stratified Random Split (80/20)** instead of chronological split. | The problem is snapshot multiclass diagnosis on arbitrary query sensor inputs, not time-series forecasting. A chronological split would concentrate early machines in train and later in test, breaking class stratification for ultra-rare classes ($N=19$). | *Chronological train/test split:* Rejected because it induces artificial machine covariate shift and starves minority classes in the test partition. |
| **3. Machine Unit (`System`)** | Contains 120 unique machine IDs ($0 \dots 119$). Failures occur across all systems (mean $2.9$ failures/machine). | **Exclude `System` from training feature matrix**. | In a production web application, the classifier must diagnose any machine based on operating sensor physics alone, without being tied to specific historical machine IDs. | *One-hot encoding 120 systems:* Rejected as it inflates dimensionality by 120 sparse columns and prevents generalization to new machine installations. |
| **4. Diagnostic Control Mode (`Control`)** | Governs which sensor channels are active (A, B, C). $\chi^2 = 659.08, p = 3.8 \times 10^{-135}$ with Diagnostic. $100\%$ of HDF are in A, $100\%$ of PWF are in B, $100\%$ of OSF/TWF are in C. | **Retain `Control` and One-Hot Encode it** as a categorical feature in the pipeline. | `Control` is an essential operational context variable indicating which physical sensor bus is active. | *Dropping `Control`:* Rejected because `Control` provides crucial domain context explaining why specific sensors are absent. |
| **5. Severe Class Imbalance** | Majority `No failure` = $96.52\%$ ($9,652$ rows). Minority failures = $3.48\%$ ($348$ rows), with `Random Failures` having only $19$ instances ($508:1$ ratio). | **Use Macro-F1 and Per-Class Recall** as primary metrics. Implement **`class_weight='balanced'`** and test **SMOTE inside cross-validation training folds**. | Standard accuracy produces $96.52\%$ for a trivial baseline predicting all normal. Macro-F1 weights all 6 failure modes equally, ensuring rare catastrophic failures are detected. | *Accuracy scoring:* Rejected as scientifically misleading and dangerous for industrial safety. *Resampling before split:* Rejected as fatal leakage. |
| **6. Realistic Missing Sensor Values** | $65.63\%$ missing in temperatures, $33.21\%$ in speed, $34.37\%$ in torque, $66.79\%$ in tool wear. $100\%$ MAR conditional on `Control`. $0$ complete rows exist. | **Benchmark Median, KNNImputer, and IterativeImputer with `MissingIndicator` flags** inside an 80% training fold CV. Select best via Macro-F1. | Dropping missing rows is impossible ($100\%$ data loss). Imputer must be strictly fitted on training folds only to prevent test set leakage and must handle single-row inputs with NaNs at web inference. | *Complete case deletion:* Rejected ($100\%$ data loss). *Class-conditional imputation:* Rejected as fatal data leakage (labels unavailable at web inference). |
| **7. Extreme Sensor Outliers** | $92.2\%$ of Torque IQR outliers ($59/64$) are actual failure events ($50$ Power Failure, $9$ Overstrain Failure). Rotational speed contains $31$ failure outliers. | **Retain all sensor outliers** without trimming or deleting. Non-tree models receive bounded scalers if needed. | Outliers represent true catastrophic failure physics. Removing outliers destroys $>60\%$ of all Power Failure instances. | *IQR outlier removal / Z-score trimming:* Rejected as it directly strips out the minority failure cases we are training the model to detect. |
| **8. Feature Scaling** | Tree ensembles (RandomForest, LightGBM) are scale-invariant, but distance/linear models (SVM, KNN, Logistic Regression) require zero mean and unit variance. | **StandardScaler integrated conditionally inside `Pipeline`** for scale-sensitive models; tree models receive unscaled data. | Preserves interpretability and physical sensor units for trees while ensuring numerical convergence and distance metric stability for SVM/KNN. | *Global scaling before split:* Rejected as imputer/scaler leakage. *MinMax scaling:* Rejected because extreme failure outliers would compress the normal operating range. |
| **9. Domain Feature Engineering** | Domain physics rules hold with $100\%$ precision: $\Delta T = T_{proc} - T_{air}$, $P = \tau \cdot \omega \cdot \frac{2\pi}{60}$, $OS = \text{Wear} \cdot \tau$. | **Engineer continuous interaction features ($\Delta T$, Mechanical Power, Overstrain Product, Missing Count)** inside an `sklearn.base.BaseEstimator` transformer. | Continuous physical representations allow linear and non-linear classifiers to easily learn failure boundaries without hardcoding brittle threshold rules. | *Hardcoding binary failure rules:* Rejected because binary flags destroy continuous probability estimates and do not generalize to borderline degradation. |
| **10. Web App Inference Architecture** | User inputs arbitrary sensor values (some potentially missing) into web UI and requests real-time diagnosis. | **Construct ONE unified `sklearn.pipeline.Pipeline`** saved with `joblib` that performs preprocessing, missing indicator generation, imputation, encoding, and classification. | Guarantees exact parity between training preprocessing and single-row inference; prevents pipeline drift and deployment bugs. | *Manual preprocessing scripts / ad-hoc scripts:* Rejected due to high deployment error risk and inability to handle missing fields natively. |
